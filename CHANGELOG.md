# История версий

## Runtime 1.5.0 — 2026-11-14

- Исправлены F01–F10: первая поставка, commit/GC моделей, общая история, DATA_DIR, восстановление политики доступа, PATCH/CAS настроек, выбор модели, контекст и черновики.
- Общие сервисы Runtime вынесены из EXE launcher. OpenAI-compatible API 1.1 поддерживает инструменты, SSE tool calls, capabilities/readiness и адресную отмену.
- Адаптер Qwen3.5 использует фактический GGUF XML-шаблон; оборванные вызовы не исполняются, tool usage сохраняет native token counts.
- Runtime больше не запускает мини-помощника; он принадлежит Workspace.

## Workspace 0.2.0 beta — 2026-11-14

- Самостоятельные EXE, версия, SQLite и каталоги данных; pinned Harness SDK/native 0.2.2rc2 и rg включены в Windows-поставку.
- Главный сценарий — диалоги с памятью или без неё. Проект, Git, файловые инструменты и Harness для общения не нужны.
- Проект может состоять только из названия; обычная папка и GitHub подключаются по желанию. Файловый агент включается явно и сохраняет разрешения, события, diff, адресную остановку и восстановление без повтора действий.
- Мини-помощник Workspace использует прежнюю нативную синюю пиксельную панель слева от аватара с указателем, выбором бесед, новым диалогом, датами и отдельными черновиками. Сохранены индикаторы ✓ / ? / … / !.
- Кнопка мини-помощника показывает персонажа; диалог открывается по нажатию на него. Главное окно и панель имеют независимый выбор беседы.
- Модели и подключения объединены в одни модальные настройки; резервные копии перенесены на вкладку «Данные». Адрес и состояние Runtime видны в шапке, его настройки открываются по ссылке.
- Schema 2 сохраняет существующие проекты и сессии schema 1; прерванный обычный ответ остаётся в истории и не отправляется автоматически повторно.
- Пример локального приложения и MCP read/write с одноразовым подтверждением, receipt и защитой от повторной отправки.
- Приёмка файлового агента с 4B: 11/20 узких задач с внесёнными регрессиями. Обычный диалог отдельно проверен реальными запросами, памятью и отменой; границы проверок перечислены в VALIDATION.

## 1.4.4 — 2026-11-14

- Общая серверная история для EXE и браузера: версии обновлений и барьеры очистки защищают сообщения от устаревших вкладок и поздних ответов.
- Ошибки ответа видны после перезагрузки; исправлены блокировки отправки, сохранение черновика, второй запуск EXE и настройки мини-помощника.
- Контекст передаётся без скрытого ограничения 64 сообщений; исправлены продолжительные диалоги Python-клиента и разбор рассуждений Qwen по данным адаптера.
- Timeout охватывает stdin worker; исправлены ложный warm, повторное использование CPU fallback, обновление весов по прежнему пути, seed и idle после прогрева.
- Настройки проверяются до записи, логотип заменяется атомарно в отдельном потоке, повреждённый реестр сохраняется для восстановления.
- Сборка сначала готовит полную поставку во временном каталоге; прежняя программа сохраняется при ошибках. Уточнены приватный перенос и публичный архив.
- Обновлены FastAPI/Starlette/multipart и инструменты frontend. Браузерные Origin/Host проверяются до изменений данных; Python/curl без Origin поддерживаются.
- Исправлены штатные диагностические скрипты, обновление примера VetConsult и Docker proxy при смене IP backend.

## 1.4.3 — 2026-11-13

- Проверка реестра и замена модели больше не перезаписывают результаты друг друга.
- Мини-помощник явно показывает ошибку оборванного или обрезанного ответа и сохраняет частичный текст.
- Нормализация и слияние длинной истории используют индекс по ID; неизменённая история кэшируется и не перечитывается при каждом UI-опросе.
- Дополнительные браузерные `/assistant` и `/assistant-overlay` используют общую проверку завершённости ответа и фильтр памяти.
- Старые сообщения с `finish_reason=length` исключаются из памяти даже при сохранённом `phase=done`.

## 1.4.2 — 2026-11-12

- Пересборка сохраняет существующие модели, настройки и оформление, включая совпадение источника и назначения данных.
- Полная история мини-помощника хранится без скрытых ограничений 120 сообщений и 40 диалогов.
- Проверены границы путей статики, upload и hub; оформление отделено от приватного хранилища.
- Замена модели атомарна, согласована с worker и не обнуляет mmap-файлы; невостребованные собственные версии очищаются, внешние файлы сохраняются.
- Прогрев и команды модели обновляют актуальный реестр без потери параллельной регистрации.
- EOF без done и незавершённые рассуждения отмечаются как неполные, не попадают в память.
- Docker принимает GGUF до 16 ГиБ, Vite использует same-origin API proxy.
- Рядом с EXE добавлены CHECK_API.bat и самостоятельный check_api.py для проверки API, памяти и SSE.

## 1.4.1 — 2026-10-05

- Сборка Windows автоматически выбирает CUDA при обнаружении NVIDIA, заранее устанавливает CUDA runtime/DLL и проверяет GPU offload до замены EXE. CPU-сборка доступна через `--cpu`.
- Мини-помощник остаётся доступным во время загрузки модели: можно перемещать окно, создавать и просматривать диалоги. Фоновый ответ сохраняется в исходном диалоге без переключения текущего просмотра.
- Исправлено изменение размеров и положение мини-помощника на дополнительных мониторах, включая отрицательные координаты рабочего стола.
- Меню контекста в обоих интерфейсах: размер и пресеты, резерв токенов на ответ, оценка заполнения, автоматическое сокращение старых реплик с сохранением всей истории. Ошибки переполнения содержат лимит и способы исправления.
- Загрузка модели выполняет пробное вычисление и прогревает обработку запроса и последующего токена. Мини-помощник сохраняет профиль загрузки выбранной модели для повторного использования worker.
- Публичный переносимый архив исключает пользовательские настройки, историю, логи и модели; включает чистый реестр, безопасные настройки и CUDA-зависимости.
- Тесты сборщика используют временную папку вывода и проходят в Docker с исходниками, подключёнными только для чтения.

- Linux NVIDIA CUDA: отдельный backend Dockerfile и Compose GPU overlay; CPU-сборка остаётся по умолчанию, проверка inference поддерживает три режима и фактические GPU-слои без fallback.
- Адаптер Qwen отключает рассуждения через штатный GGUF-шаблон; переключатель в настройках и `chat_template_kwargs.enable_thinking` в API.
- Проверенный Linux Docker CPU: отдельные образы backend/frontend, persistent volume, read-only GGUF mount, healthcheck и SSE через Nginx.
- Исправлена потеря JSON heartbeat при тихой нативной загрузке модели; stderr читается отдельно с ограниченным буфером.
- CI проверяет регрессии на Windows/Linux и Docker web/API; README обновлён с иллюстрациями, справкой и клиентом Python.

- Постоянный изолированный inference worker, отдельное чтение stderr, ограниченные таймауты, отмена и восстановление после сбоя.
- Память отдельных диалогов в браузере и мини-помощнике; memory=true/false в API.
- Компактный сине-белый браузерный чат и настройки CPU/CUDA/прогрева.
- Стандартный OpenAI-compatible SSE, пример клиента и справка API/VetConsult.
- Переносимый CUDA runtime, исправление version define в Vite и безопасная запись истории.
- Дата и время сообщений в основном чате и мини-помощнике; время создания сохраняется при потоковых обновлениях.
- Иконка с детализированной головой мини-агента для EXE, заголовка окна, панели задач и трея.
- Скрываемая панель выбора/создания диалогов мини-помощника, разнесённые реплики и сохранение ручной позиции прокрутки.
- CUDA runtime обновлён до llama-cpp-python 0.3.36; CPU отключает KV/operation offload, диагностика сохраняет фактическое число GPU-слоёв.
- Относительные пути packaged-моделей сохраняются при изменении реестра и переносе папки dist.
