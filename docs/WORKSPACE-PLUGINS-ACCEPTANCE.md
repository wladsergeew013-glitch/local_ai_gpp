# Проверка пакетов навыков Workspace 0.2.9

22 ноября 2026 года. Windows, TDMS Project Manager 0.7.47, Local AI Runtime 1.5.0,
Qwen3.5-4B Q4_K_M. Профили и порты приёмки были отдельными. Проверки транспорта и
результатов выполнялись с реальным TDMS и с детерминированными тестовыми ответами.

| Проверки ТЗ | Результат |
| --- | --- |
| AC-01–03, AC-11 | Один манифест устанавливает пять навыков TDMS при выключенном приложении. Перенос папки `Skills` восстанавливает инструкции и ID в чистом профиле. |
| AC-04, AC-08–10 | TDMS запускался из отдельного каталога. Повторный импорт на новый рабочий порт сохранил пять ID и отдельное выключение DWG. Обновление с удалённым навыком оставляет старую ссылку распознаваемой. |
| AC-05–07 | Принят ранний синтаксис `tool`. Неверный манифест, отсутствующий Markdown, выход за каталог и конфликт полей отклонены. Прерывание записи пакета проверено откатом SQLite при ошибке обновления. |
| AC-12 | Контрактный тест дочернего агента подтвердил отдельный ID вызова, общий каталог, проверку включения и доступ только к переданному файлу задачи. |
| AC-13 | Реальная модель проверена через Runtime. Для HTTPS-провайдера проверена нормализация запросов без полей Runtime. Прогон с внешним провайдером остаётся отдельной проверкой с его учётными данными. |
| AC-14–15 | Проверены автоматический выбор проекта, явный выбор навыка и цепочка из двух MCP-инструментов в отдельном навыке. Qwen на CPU передала созданный `.tdmsproj` второму инструменту по ID. |
| AC-16–19 | Отсутствующую зависимость, неверные аргументы, чужие и неоднозначные вложения отклоняет Workspace. Неполный набор DWG отклоняет TDMS. Base64 формируется после проверки в Workspace. |
| AC-20–21 | Из реального Workspace получены оба файла проекта и PDF с закладками. В PDF подтверждены закладки, в итоговом проекте четыре DWG и ноль ошибок валидации. Частичный ответ, предупреждения и сбой отдельного ресурса проверены тестами MCP. |
| AC-22–26 | Тесты подтвердили очередь, изоляцию результатов отдельных задач, приостановку после потери ответа, независимость второго плагина, снимок при обновлении, `tools: []` и вызов без вложений. |
| AC-27 | Пять ID извлечены из действующего профиля Workspace 0.2.8 и перенесены по фактическим связям с инструментами. Идемпотентность проверена повторным импортом. |

Соответствие для переноса определяется сохранённым источником TDMS на `127.0.0.1:8788`,
группой `tdms`, именем навыка и привязанным инструментом. Сам номер ID берётся из
обновляемого профиля.

| Навык в профиле 0.2.8 | Инструмент MCP | Имя в пакете TDMS v2 |
| --- | --- | --- |
| `tdms-stamps` | `stamp_people` | `tdms-stamps` |
| `tdms-pdf-bookmarks` | `pdf_bookmarks` | `tdms-pdf-bookmarks` |
| `tdms-project` | `tdms_project_prepare` | `tdms-project` |
| `tdms-dwg` | `tdms_match_drawings` | `tdms-dwg` |
| `tdms-validate` | `tdms_validate` | `tdms-validate` |

В отдельном CPU-профиле Qwen выполнила создание проекта и привязку четырёх DWG.
Во время проверки исходного CUDA-профиля истёк лимит модельного шага. Остановка
ожидания ответа модели покрыта регрессионным тестом. Один существующий Windows-тест
символических ссылок пропущен из-за прав Windows на их создание.
