# Пакеты навыков Workspace

## Подключение приложения

В настольном Workspace откройте **Настройки → Навыки → Импортировать пакет навыков**.
Выберите `skills/manifest.json` из папки приложения. Workspace прочитает соседние
Markdown-файлы и сохранит пакет целиком. Импорт можно выполнить до запуска приложения.
После импорта группа и её навыки активны. Там же можно проверить соединение и выключить
группу или отдельную операцию. В меню диалога действие **Применить к следующей реплике**
явно выбирает инструкцию конкретного навыка.

TDMS запускает MCP при обычном запуске EXE. Адрес задаётся кнопкой **Адрес MCP…** на
экране выбора модуля TDMS. После применения адреса TDMS сам сохраняет его в `skills/manifest.json`.
Повторно импортируйте этот манифест в Workspace. Существующие ID, ссылки чатов и выключения
сохранятся. Для вызовов Workspace использует адрес из установленной копии пакета.

Для отдельного профиля или запуска без окна доступен импорт из командной строки.

```powershell
LocalAIWorkspace.exe --data-dir "C:\Workspace-QA" --import-skills "D:\TDMS\skills\manifest.json"
```

## Что поставляет приложение

В одном каталоге лежат `manifest.json` и перечисленные в нём Markdown-файлы. Относительные
пути начинаются от каталога манифеста. В `product`, `skillGroup.id` и `skills[].name`
записываются постоянные идентификаторы. Видимые названия, версии, пути и URL можно менять
при обновлении. В `tools[]` перечисляются обязательные инструменты навыка. У отдельного
инструмента допустима привязка одного файла `file`, набора `files` или только смысловые
параметры по его JSON Schema. Инструкции с `tools: []` доступны без MCP.

Первоначальную форму v2 с `tool` и `file` либо `files` на уровне навыка Workspace
приведёт к `tools[]`. Если в этой форме отсутствует версия, интерфейс покажет «не указана».

[JSON Schema v2](../workspace/schema/skill-package-v2.json) ·
[Пример навыка с двумя инструментами](../examples/workspace-skill-package/manifest.json)

Локальный endpoint использует Streamable HTTP. Workspace согласует версию, передаёт
идентификатор сессии при его наличии, проверяет весь список инструментов и валидирует
окончательные аргументы по `inputSchema`. В результатах поддерживаются встроенные ресурсы,
`resource_link` через `resources/read` того же приложения и `workspaceResultVersion: 1`
в `structuredContent`. Файлы сохраняются с собственными идентификаторами задачи.
Следующий вызов может передать полученный файл по этому идентификатору.
[Транспорт MCP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) ·
[Инструменты MCP](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) ·
[Ресурсы MCP](https://modelcontextprotocol.io/specification/2025-11-25/server/resources)

Модель получает инструкции выбранного навыка, определения инструментов для смысловых
аргументов и идентификаторы файлов. Workspace собирает и отправляет байты приложению.
В настройках модели можно использовать локальный Runtime или HTTPS-провайдер с
OpenAI-совместимым `chat/completions`. Ключ модели задаётся отдельно от подключения MCP.

Файловый агент получает тот же каталог через инструменты Workspace. Он может передать
подзадачу дочернему агенту с одним выбранным навыком и перечисленными файлами задачи.
Дочерний агент использует снимок выполнения и общую очередь плагина. Его вызовы
сохраняются с собственным идентификатором агента.

## Хранение и восстановление

Workspace атомарно сохраняет манифест, файлы, внутренние ID и ревизию в
`<профиль>\Skills\packages.sqlite3`. Ревизия зависит от содержимого манифеста и Markdown.
При замене пакета начатый запрос продолжает работу со своим снимком. Явное выключение
навыка или группы проверяется перед каждым новым вызовом. Удалённый при обновлении
навык по старой ссылке помечается как удалённый.

После закрытия Workspace папку `Skills` можно перенести внутрь нового профиля.
Диалоги, настройки включения и ключи v2 хранятся в `workspace.sqlite3` основного профиля.
Штатный снимок данных Workspace включает обе базы. Для плагина с авторизацией ключ
сохраняется отдельно для его текущего URL.

Вызовы одного плагина идут последовательно. При потере ответа после отправки операции
Workspace приостанавливает его очередь. В **Настройки → Навыки** её можно возобновить
после проверки, что предыдущая операция завершилась, или после перезапуска приложения.
В профиле остаются время начала и конца, ID задачи, агента и вызова, ключ навыка,
ревизия и статус. Открытый в старом процессе вызов при старте Workspace помечается
как операция с неизвестным исходом.

## Лимиты Workspace

| Параметр | Значение |
| --- | --- |
| Манифест / Markdown / пакет | 256 000 байт / 128 000 байт / 2 МиБ |
| Навык в пакете / зависимости навыка | До 128 навыков / до 64 инструментов |
| Входные файлы на вызов | До 12 МиБ на файл и до 48 МиБ суммарно до Base64 |
| Выходные файлы на вызов | До 32 файлов и до 64 МиБ суммарно после декодирования |
| Смысловые аргументы | До 256 000 байт JSON |
| Шаги цикла инструментов | До 12 на применение навыка |
| Таймаут соединения | 4 с, `LOCAL_AI_MCP_CONNECT_SECONDS` |
| Таймаут запроса инициализации и каталога | 20 с, `LOCAL_AI_MCP_SETUP_SECONDS` |
| Таймаут вызова инструмента | 900 с, `LOCAL_AI_MCP_TOOL_SECONDS` |

Приложение может дополнительно ограничить размер или состав входных файлов через схему
и проверку бизнес-операции. TDMS 0.7.47 принимает до 12 МиБ файлов на вызов.
